# Допущения и решения

Сюда записываются решения, принятые без полной информации, и их обоснование. Если допущение
подтвердилось или опровергнуто — пометьте это здесь, а не удаляйте запись.

Статусы: **принято** — решение действует; **проверить** — нужна сверка с источником или прогоном;
**подтверждено** — проверено, указано чем.

## Исходники и сборка

| № | Допущение | Статус | Обоснование / где проверить |
|---|---|---|---|
| B1 | Источник истины — тексты ST в `src/`, `.project` в git не хранится | принято | `.project` бинарный: его нельзя ревьюить и сливать. Готовые `.project` и `.library` прикладываются к релизам GitHub |
| B2 | Свойства в `build/assembled/` записываются в синтаксисе RuSTy: `PROPERTY_GET <Имя> : <тип> ... END_PROPERTY`, `PROPERTY_SET ...` | принято | В МЭК 61131-3 ред. 3 свойств нет; RuSTy понимает такой синтаксис. Собранный текст нужен только анализаторам и в CODESYS не импортируется |
| B3 | Вариант сборки `iec-checker` понижает конструкции, которые не разбирает iec_checker (методы внутри ФБ, `EXTENDS`, прагмы) | принято | Только для статанализа; семантика собранного текста может отличаться от исходной |
| B4 | GVL объявляются с `{attribute 'qualified_only'}`, обращение — `GVL_Const.ИМЯ` | принято | Рекомендуемая практика CODESYS: нет конфликтов имён. RuSTy не знает имён GVL — вариант сборки `rusty` убирает префикс `GVL_Const.` (проверено: `plc --check` по `build/assembled/rusty/` проходит) |
| B5 | Режимы в `FB_Example` разбираются `CASE` по перечислению `E_DeviceMode` | принято | iec_checker 0.4 не разбирает метки `CASE` вида `E_DeviceMode.Auto` и неконстантные начальные значения (`:= E_DeviceMode.OutOfService`, `:= GVL_Const.ИМЯ`). Код пишется для CODESYS, а понижение — забота варианта сборки `iec-checker`: метки заменяются целыми значениями, неконстантные начальные значения убираются |
| B6 | Строковые литералы `STRING` (имена тестов, сообщения CfUnit) — только ASCII | принято | Кириллица в `STRING` зависит от кодовой страницы среды и рантайма. Комментарии остаются русскими |
| B7 | Обязательный статанализ в CI — iec_checker v0.4 (тот же, что локально); образ `nightly` — необязательное задание | принято | Обоснования в `iec_checker_allow.toml` подобраны под находки v0.4: с другой версией разборщика обязательная проверка зависела бы от его изменений. Бинарник v0.4 закреплён по размеру и SHA-256 (у релиза нет опубликованной суммы — она вычислена по файлу), образ `nightly` — по дайджесту |

## Пример и тесты

| № | Допущение | Статус | Обоснование / где проверить |
|---|---|---|---|
| C1 | Семантика `F_Clamp` — см. раздел ниже | принято | Покрыта тестами `FB_F_Clamp_Test` |
| C2 | `FB_Example` — двухпозиционный регулятор с гистерезисом ниже уставки: включение при `значение <= уставка - гистерезис`, отключение при `значение >= уставка` | принято | Типовая схема насоса подкачки: уставка — уровень отключения, гистерезис отсчитывается от неё вниз. Оператору понятнее, чем зона, симметричная относительно уставки |
| C3 | Режим по умолчанию у `FB_Example` и в `ST_ExampleCmd` — `OutOfService` | принято | До явного назначения режима выход в безопасном состоянии |
| C4 | В режиме `Local` выход ПЛК — `FALSE` | принято | Управляют с местного поста; команда ПЛК снимается. В реальном проекте — сверить со схемой управления (как местный пост блокирует команду ПЛК) |
| C5 | Отказ измерения фиксируется только в `Auto` и снимается квитированием, если измерение снова достоверно | принято | В `Manual` оператор управляет сам, измерение на выход не влияет |
| C6 | Фреймворк тестов — CfUnit в актуальной версии 1.2.0.0, где он переименован в **coUnit** (co♻e). В коде пространство имён `coUnit`: набор — `FUNCTION_BLOCK ... EXTENDS coUnit.FB_TestSuite`; в методах-тестах — функции **с пространством имён** `coUnit.TEST('<имя>')`, `coUnit.TEST_FINISHED()` и методы базового ФБ без него (`AssertEquals_REAL(Expected :=, Actual :=, Delta :=, Message :=)`); в `PRG_Tests` — `coUnit.RUN()` и флаг `AreAllTestsFinished()` | подтверждено | Сборка в CODESYS 3.5.17.30 и прогон в Control Win V3 (16.10.2026, `cds.py test`). Без пространства имён `TEST`/`TEST_FINISHED` дают ошибки C0046/C0035 — исправлено в `tests/`. Библиотека 1.2.0.0 открывается в SP17 Patch 3, зависимости находятся |
| C7 | Параметры библиотеки coUnit по умолчанию (1000 наборов × 100 тестов) не уменьшаются | подтверждено (Control Win) / **проверить** (ПЛК210) | Тестовое приложение с параметрами по умолчанию собирается под CODESYS Control Win V3 без ошибок, C0106 нет (сборка 16.10.2026: 0 ошибок, 0 предупреждений). Ранее предполагалось уменьшение до 10–20 наборов из-за ~78 МБ памяти — для ПЛК210 с меньшей памятью сверить при переносе тестов на контроллер (параметры — в Library Manager, `ScriptLibraryReference.parameters`) |
| C8 | Ожидаемые значения в тестах `F_Clamp` не равны нулю | принято | Выход функции без реализации равен 0: тест с ожиданием 0 прошёл бы ложно |
| C9 | В тестах `FB_Example_Test` проверяемый экземпляр — локальная переменная метода (`fbDut : FB_Example` в `VAR` метода), каждый тест укладывается в один цикл | подтверждено | Локальные переменные метода инициализируются при каждом вызове, поэтому тест всегда начинает с нового экземпляра и не зависит от того, что раннер coUnit вызывает метод каждый цикл. Счётчик проверяется после проверки ненулевого значения: проверка `Count = 0` после `Reset()` не может пройти ложно. Набор проверен RuSTy и iec_checker, собран в CODESYS 3.5.17.30 и пройден в Control Win V3 (11 из 11, 16.10.2026, `cds.py test`) |

## Семантика F_Clamp

`F_Clamp(rValue, rLow, rHigh)` возвращает `rValue`, ограниченное отрезком между границами.

- Границы включаются: `F_Clamp(rLow, rLow, rHigh) = rLow`, `F_Clamp(rHigh, rLow, rHigh) = rHigh`.
- **Если `rLow > rHigh`, границы меняются местами.** Результат всегда лежит между двумя заданными
  числами и не зависит от порядка аргументов. Альтернативы были такие: вернуть `rLow` или повторить
  поведение `LIMIT` (`MIN(MAX(IN, MN), MX)` при `MN > MX` всегда даёт `MX`). Обе дают результат на
  одной из границ при любом входе, и ошибку конфигурации легко не заметить. Функция с результатом
  `REAL` не может сообщить об ошибке, поэтому выбрано поведение без скачков.
- Вырожденный отрезок `rLow = rHigh` — результат всегда равен границе.
- NaN не обрабатывается: при `rValue = NaN` результат — NaN. Достоверность измерения проверяется
  до вызова (NAMUR NE 43 — в ФБ аналогового входа).
