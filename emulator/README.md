# kns-emulator — эмулятор ПЛК КНС-1

Эмулятор нужен, чтобы стенд «от датчика до дашборда» работал без CODESYS: в CI, на демонстрации и
при разработке дашбордов. Он делает то же, что приложение ПЛК флагмана (проект 02) на
CODESYS Control Win: поднимает OPC UA-сервер с тем же адресным пространством, публикует
телеметрию и тревоги в MQTT по схеме данных стенда и принимает команды с проверками шлюза.
За ним — простая детерминированная модель объекта: резервуар, приток с суточной кривой и
«ливнями», насосы с ПЧ, чередование по моточасам, тревоги и инъекция отказов.

Объект вымышленный; параметры модели условные и не описывают реальный насос или станцию.

## Состав пакета

| Модуль | Что делает |
|---|---|
| `tagmodel.py` | перечень тегов флагмана: `data/scada_tags.csv` и `data/scada_alarms.csv` (генератор iolistgen) |
| `devices.py` | поведение устройств plc-process-lib «снаружи»: режимы, импульсные команды, `stSts`, NE 107, тревоги, счётчики, рампа ПЧ |
| `alarms.py` | слот тревоги по ISA-18.2 (задержка, квитирование, shelve, вывод из работы) и события |
| `plant.py` | модель объекта: баланс резервуара, приток, характеристики насосов и сети, павильон |
| `station.py` | логика станции: уровни, роли duty/assist/standby, АВР, защиты, питание, вентиляция |
| `faults.py` | каталог отказов и автоматический сценарий демонстрации по зерну |
| `emulator.py` | цикл ПЛК (входы → станция → устройства → выходы → модель), образ тегов, запись команд |
| `opcua_server.py`, `pki.py` | OPC UA-сервер (asyncua), пользователи, политики, сертификат |
| `schema.py` | топики, каталог телеметрии, белый список, построение сообщений по `schema/*.schema.json` |
| `telemetry.py` | выбор сообщений: по изменению с зоной нечувствительности и периодически |
| `commands.py` | шлюз команд MQTT: проверки раздела 5.1 docs/data_schema.md |
| `mqtt_link.py` | клиент paho-mqtt (API v2): LWT, рождение, публикация, подписка на команды |
| `app.py`, `cli.py` | приложение в реальном времени и командная строка `kns-emulator` |

Копии контракта стенда (`schema/source/*.csv`, `schema/telemetry_catalog.csv`,
`schema/command_whitelist.csv`, `schema/topics.json`) лежат в `iiot_emulator/data/`: образ
Docker собирается из каталога `emulator/`. Тест `test_schema_copies_match_repo` падает, если копия
разошлась с `schema/`; обновление — простым копированием файлов.

## Быстрый старт

```bash
python -m pip install -e emulator               # из корня репозитория; Python 3.11+
kns-emulator simulate --hours 24                 # без сети: прогон модели и сводка
kns-emulator run --env-file .env                 # OPC UA + MQTT по переменным EMU_* из .env
kns-emulator run --no-mqtt --time-factor 600     # только OPC UA, сутки модели за 2,4 минуты
kns-emulator tags opcua                          # узлы OPC UA (814) и права R/RW
kns-emulator faults                              # отказы для узлов Simulation.Inject
```

В составе стенда эмулятор запускается командой `make demo` (сервис `emulator`, профиль `demo`,
образ `docker/emulator.Dockerfile`).

## Переменные окружения

Секреты — только в `.env` (в git — `.env.example`). Docker compose передаёт в `EMU_*` значения
общего `.env` стенда.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `EMU_SEED` | `1` | зерно модели: приток, «ливни», сценарий отказов, шум измерений |
| `EMU_TIME_FACTOR` | `60` | модельных секунд за секунду (60 — сутки за 24 минуты) |
| `EMU_STEP_S` | `1.0` | модельный шаг цикла ПЛК, с |
| `EMU_TICK_S` | `0.25` | период обмена с OPC UA и MQTT, реальные секунды |
| `EMU_START_HOUR` | `6` | модельное время суток при старте |
| `EMU_AUTO_FAULTS` | `true` | автоматический сценарий отказов (по зерну) |
| `EMU_AUTO_ACK_S` | `900` | «диспетчер» квитирует тревоги через столько модельных секунд; `0` — нет |
| `EMU_OPCUA_ENABLE` | `true` | OPC UA-сервер |
| `EMU_OPCUA_ENDPOINT` | `opc.tcp://0.0.0.0:4840` | адрес сервера |
| `EMU_OPCUA_USER`, `EMU_OPCUA_PASSWORD` | — | пользователь с правом записи команд |
| `EMU_OPCUA_ALLOW_ANONYMOUS` | `false` | анонимный клиент — только чтение |
| `EMU_OPCUA_PKI_DIR` | `pki` | ключ и сертификат сервера (в .gitignore) |
| `EMU_OPCUA_HOSTNAME` | имя компьютера | DNS-имя в сертификате |
| `EMU_OPCUA_NS`, `EMU_OPCUA_DEVICE_NAME` | `4`, `CODESYS Control Win V3` | номер пространства имён и имя устройства в идентификаторах узлов |
| `EMU_MQTT_ENABLE` | `true` | MQTT |
| `EMU_MQTT_HOST`, `EMU_MQTT_PORT` | `localhost`, `1883` (`8883` с TLS) | брокер |
| `EMU_MQTT_USER`, `EMU_MQTT_PASSWORD` | — | пользователь брокера с ролью ПЛК |
| `EMU_MQTT_TLS`, `EMU_MQTT_CA_FILE` | `false`, — | TLS и сертификат УЦ брокера |
| `EMU_MQTT_PERIOD_S` | `60` | контрольная публикация всех метрик (`period_ms` в рождении) |
| `EMU_MQTT_CMD_MAX_AGE_S` | `30` | допуск возраста команды (`expired`) |
| `EMU_MQTT_CMD_RATE_LIMIT`, `EMU_MQTT_CMD_RATE_WINDOW_S` | `10`, `10` | не больше N команд за окно (`rate_limited`) |
| `EMU_MQTT_SITE`/`AREA`/`UNIT`/`NODE` | из `topics.json` | уровни топиков, если нужно переопределить |
| `EMU_LOG_LEVEL` | `INFO` | журнал |

Без пароля OPC UA сервер не стартует, если не разрешён анонимный доступ.

## OPC UA

- **Узлы** — как у символьной конфигурации CODESYS: `ns=4;s=|var|CODESYS Control Win V3.Application.<путь>`,
  пути и типы — из `scada_tags.csv` (814 переменных). Обзор:
  `Objects/DeviceSet/CODESYS Control Win V3/Resources/Application/GVL_Devices/fbLT101/stSts/rValue_eu`.
  Номер пространства имён 4 и имя устройства — как в перечне; у настоящего рантайма их сверяют
  по обзору сервера (пространства 2–3 у CODESYS заняты моделями DI и PLCopen, у эмулятора это
  резерв).
- **Типы** — как в ПЛК: BOOL → Boolean, INT → Int16, WORD и UINT → UInt16, UDINT → UInt32,
  REAL → Float. Запись другого типа — `BadTypeMismatch`.
- **Запись** — только в `GVL_Hmi.st<DEV>Cmd.*`. Импульсные биты и маски эмулятор сбрасывает после
  обработки в ближайшем цикле, как ФБ библиотеки (API 2.1): клиент видит `TRUE → FALSE`, рост
  `uiCmdSeq` и `eCmdResult`. Значения (`rSpeedSp_pct`, `rSubstValue_eu`) не сбрасываются; вне
  Manual ФБ пишет в них текущее значение (слежение).
- **Безопасность**: конечные точки `None` и `Basic256Sha256 Sign&Encrypt`; самоподписанный
  сертификат создаётся при первом запуске в `EMU_OPCUA_PKI_DIR` (`server_cert.der` кладут в
  доверенные клиента). Пароль по каналу `None` клиент шифрует сертификатом сервера (политика
  токена Basic256Sha256). Анонимно — только чтение и подписки.
- **Узлы эмулятора** (пространство `urn:plc-iiot-stack:kns-emulator:simulation`):
  `Simulation.SimTime_s`, `SimHour`, `Inflow_m3h`, `PumpsRequired`, `DutyPump`, `Emergency`,
  `Degraded`; запись `TRUE` в `Simulation.Inject.<отказ>` включает отказ (`kns-emulator faults`).

## MQTT

Топики, сообщения и проверки — по `docs/data_schema.md` и `schema/*.schema.json`:

- `vodokanal/kns1/station/<device>/<metric>` — телеметрия по каталогу (123 метрики), QoS 1,
  retain; по изменению (зона нечувствительности каталога, не чаще раза в секунду на метрику,
  изменение `quality` — сразу) и контрольная публикация раз в `EMU_MQTT_PERIOD_S`.
  `quality` — по NE 107 и `xValid` устройства-источника (раздел 3.2), метрики ПЧ при потере
  связи — `bad`.
- `.../<device>/alarm/<suffix>` — событие тревоги (QoS 1, retain). Без связи события ждут в
  очереди (до 1000) и уходят по порядку. После рождения публикуется состояние каждой из 75 тревог:
  последнее событие с исходным `ts` или «норма» с моментом старта.
- `.../PLC1/status/connection` — завещание offline/lwt, рождение online/birth (`source: emulator`,
  `period_ms`), штатная остановка offline/shutdown.
- `.../<device>/cmd/<command>` → `.../<device>/cmd_ack/<command>` — команды с белым списком и
  проверками по порядку раздела 5.1: retain, состав, версия, топик, белый список, диапазон,
  возраст, повтор (последние 16), частота (10 за 10 с). Прошедшая команда пишется в
  `GVL_Hmi`, ответ — по `eCmdResult` устройства (`ok`, `device_rejected` + `cmd_result`,
  `timeout`); команды-значения (`SpeedSp`) — `ok` после записи.
- `.../PLC1/<metric>` — диагностика узла: `uptime`, `reconnects`, `queue`, `dropped`,
  `cmd_accepted`, `cmd_rejected` (в `cmd_rejected` входят и сообщения без читаемого `cmd_id`).

## Модель объекта

| Параметр | Значение (условное) |
|---|---|
| Резервуар | 15 м², уровень 0–5 м; старт — 1,4 м |
| Приток | средний сухой 95 м³/ч, суточная кривая (ночь ≈ 0,54, утренний пик ≈ 1,9 среднего), медленный шум ±6 % |
| «Ливни» | с вероятностью 0,6 в модельные сутки, пик 180–430 м³/ч, 1–3,5 ч: подъём 25 %, экспоненциальный спад |
| Насос | `H = 40·s² − 3,36·10⁻⁴·Q²`, м; один насос ≈ 240 м³/ч, два ≈ 360, три ≈ 410 |
| Сеть | `H = 12 − L + 1,24·10⁻⁴·Q²`, м; манометр PT201 — статический столб 11,5 м плюс потери |
| ПЧ | рампа ФБ 5 %/с, разгон ПЧ 10 %/с, реле «в работе» через 1 с; минимум 60 % |
| Ток двигателя | 7,5 А · s + 19,5 А · нагрузка; засор колеса: подача меньше, ток +35 % |
| Павильон | температура 16 ± 3,5 °C по суткам, H₂S и CH₄ — фон и рост при высоком уровне, вентилятор снижает |

Логика станции (допущения эмулятора; уставки флагмана задаст `04_algorithms.md` проекта 02):
ведущий насос — пуск на 1,8 м, останов всех на 0,9 м, скорость 60…100 % пропорционально уровню
0,9…2,4 м; второй насос — при 100 % и уровне ≥ 2,6 м дольше 20 с, отключение на 1,5 м;
HH (4,0 м) или поплавок LS102 — пуск всех исправных до 3,2 м; новый пуск — насос с наименьшими
моточасами; смена ведущего после 6 ч непрерывной работы; АВР при отказе запрошенного насоса;
сухой ход (LS103 или LL) — блокировка `wInterlock.0`; перегрев обмотки — `wInterlock.1`; отказ
уровнемера — деградированный режим по поплавкам; после восстановления питания насосы пускаются
по одному, следующий — через 10 с после выхода предыдущего в работу. Параметры устройств
(tMinStop 30 с, 10 пусков в час, гистерезисы, фильтры) — из колонки `params` перечня КНС.

Автоматический сценарий (по зерну, для каждых модельных суток): авария ПЧ с последующим сбросом,
обход павильона (дверь), выброс H₂S, кратковременная потеря связи с ПЧ, засор колеса,
пропадание питания. Прогон с тем же `EMU_SEED` повторяется в точности: приток и сценарий — чистые
функции (зерно, время), шум — из собственного ГПСЧ эмулятора.


|---|---|

| `test_model.py` | детерминизм по зерну, приток как функция (зерно, t), импульсы и маски, рампа, ливень, чередование, АВР, обрыв LT101, сухой ход, пропадание питания, OOS |

| `test_schema_messages.py` | каждое сообщение эмулятора (телеметрия, тревоги, ответы, состояние узла) по JSON Schema, все причины тревог и ответов, срез тревог после переподключения |

нет Docker и Mosquitto). С настоящим Mosquitto эмулятор проверяется в docker compose стенда
(`make demo`, `make test-stack`).

## Ограничения

- Это эмуляция поведения библиотеки «снаружи», а не её порт: внутренние таймеры, LKG
  конфигурации и все биты `wCfgErr` не моделируются (`wCfgErr = 0`).
- Логика станции и её уставки — допущения эмулятора до готовности проекта 02.
- Метки времени MQTT — реальное время публикации; модельное время идёт в `EMU_TIME_FACTOR` раз
  быстрее (моточасы, суточная кривая).
- Узлы OPC UA символов — переменные без типов структур CODESYS: клиент, который читает `stSts`
  целиком как структуру, работать не будет; поля читаются по отдельности.
